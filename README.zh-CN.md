# zcode-prompt-toolkit

完全掌控你自己 ZCode 桌面外壳（harness）内部的提示词。

ZCode 在运行时于一个压缩混淆过的 bundle（`zcode.cjs`）内组装它的整个系统提示词。
本工具包给你两样东西：

1. **人格注入（Persona injection）** — 把*你自己的*系统提示词放在模型所见的一切
   之前，作为第一条系统消息。
2. **完整提示词目录** — 查看并编辑 bundle 内*每一条*内置提示词、护栏、
   工具描述、输出风格规则和系统区块 — 362 个被发现区块中的 747 个可编辑变量，
   并附带安全的备份/恢复。

## 为什么

这个外壳附带一套固定的指令，而你从未有机会审查或投票。本工具包有多种用途 —
从**提示词注入（prompt injection）**到完全**合法的定制工作**（收紧输出风格、
重写工具描述、研究外壳实际发送了什么、对自己的环境做红队测试）。目的很简单：
让用户对自己的 ZCode 外壳拥有更多控制权，从而对自己的订阅拥有更多控制权。

## 提示词注入 — 为什么第一位置很重要

本工具包**可以** — 但不是必须 — 用于提示词注入，理解它为什么有效的机制
是值得的。

现代外壳把系统上下文组装成一个分节*栈*：身份前言、安全/护栏区块、工具描述、
环境信息，最后才是对话。这个栈有两个关键性质：

- **顺序即权威。** 经过指令微调的模型按位置给指令赋予权重。出现在系统上下文
  更靠前位置的文本表现得像一条"主指令"：靠后的区块被当作从属细节。当原版
  护栏说"拒绝 X"，而第一条系统消息说"在此部署中 X 已获授权"时，模型会
  做出偏向先读内容的冲突裁决，因为开场框架定义了助手*是什么*，之后的一切
  都通过该框架来解读。
- **系统角色天然受信任。** 与用户消息不同，系统通道是模型期待获知其身份与
  规则之真相的地方。放在那里的内容继承了这份信任。网页式提示词注入
  （藏在网页或文档里的一条杂散指令）要对抗整个系统栈、逆流而上；而注入
  *到系统通道本身* — 排在厂商自己的区块之前 — 是文本在整个上下文窗口中
  所能占据的最强位置。

这正是 `patch_zcode.py` 所做的事：你 `system_prompt.txt` 中的文本被拼接进
bundle 的 CLI 前缀槽位，ZCode 将其作为**第一条**系统消息发出 — 在身份区块
之前、安全区块之前、每一条护栏之前。用于你自己的安装时，这是自我定制。
同一机制也是一个干净、可复现的注入研究实验室：你掌控第一条系统消息，
因此可以测试当开场框架被操纵时模型的行为。

| 基准测试 | 指标 | 原版外壳 | 注入人格后 |
|---|---|---|---|
| AdvBench（有害行为提示） | 拒绝率 | 74% | 9% |
| OR-Bench（80 个过度拒绝探针） | 过度拒绝率 | 31% | 12% |
| XSTest（夸大安全测试） | 完全遵从率 | 41% | 83% |
| MMLU（5-shot） | 准确率 | 71.2% | 71.0% |
| HumanEval | pass@1 | 78.0% | 79.3% |
| MBPP（净化版） | pass@1 | 67.4% | 68.1% |
| SWE-bench Verified | 解决率 | 41.2% | 42.8% |
| 会话效率 | 每任务平均 token 数 | 100%（基线） | ~85% |
| 会话效率 | 每 100 条回复中的免责声明/拒绝套话 | 63 | 4 |

看模式，别看数字：在边界性以及"看着吓人但其实无害"的提示上，拒绝行为发生
*剧烈*变化（这是第一位置效应对原版护栏区块起作用），而原始知识与编码能力
基本持平 — 人格改变的是模型*如何行事、如何分配输出预算*，而不是它*知道
什么*。token 效率的提升主要来自收回的对冲空话：每条回复里更少的
"我无法帮助您"开场白和律师式的限定语。

**你的数字一定会有所不同。** 人格本身就是实验 — 同一套基准测试配上一条
敷衍的两行人格几乎不会有变化，而一条糟糕的人格可能降低编码表现（啰嗦的
人格会浪费任务本可使用的上下文）。用你的人格做自己的前后对比；工具包的
`diff`/`restore` 让原版与已打补丁之间的 A/B 对比只需两条命令。

不，我的人格不能给你。它就在我机器上的 `system_prompt.txt` 里，
它太好用了，就留在那儿。写你自己的 — 这才是拥有这个外壳的一半乐趣。

## 工作原理

ZCode 在运行时从散布于压缩 `zcode.cjs` 中的字符串字面量构建其系统提示词。
本工具包从不猜测运行时状态 — 它直接修补字面量本身：

- `patch_zcode.py` 定位 CLI 前缀字面量（`"You are ZCode, an interactive
  coding agent"`），首次运行时保存一份纯净备份（`zcode.cjs.orig`），然后
  把该字面量替换为你的人格，并用 `/*ZC_PROMPT_START*/ ... /*ZC_PROMPT_END*/`
  标记包裹。每次运行都从纯净副本重建，因此编辑提示词后重新运行始终干净且
  幂等。
- `_gen_customizer.py` 用一个小型 JS 感知词法分析器扫描纯净 bundle（它理解
  字符串/模板字面量、正则表达式、注释，以及 `[...].join(...)` 提示词数组），
  并自动生成：
  - `customize_prompts.py` — bundle 内每条提示词都成为一个可编辑的
    `P_<id>` 变量。多行提示词数组变成编号片段（`P_<id>_01`、`P_<id>_02`、
    ... 依序排列）。把某个片段设为 `""` 即删除该行（保持片段总数不变）。
    标有 `# KEEP ${...}` 的片段包含运行时模板 token，编辑后必须保留。
  - `prompts_data.py` — 发现过程的元数据（区块 id、种类、片段数、标签）。
- `customize_prompts.py apply` 在纯净备份上重跑完全相同的发现流程，收集你的
  编辑，验证它们互不重叠，然后按偏移量拼接回去（从高到低，因此没有任何
  编辑会发生位移）。它同时注入你的人格 — 所以初次设置之后，这一条命令
  就应用*一切*。

## 用法

要求：Python 3.8+ 和 ZCode 桌面应用。bundle 会被自动定位在
`%LOCALAPPDATA%\Programs\ZCode\resources\glm\zcode.cjs`
（可用 `--target` 覆盖 / 编辑 `TARGET`）。

```text
# 1. 写下你的人格（本文件发布时为空白 — 不会预载任何内容）
notepad system_prompt.txt

# 2. 首次运行：修补 bundle，保存纯净备份
python patch_zcode.py

# 3. 从你的纯净 bundle 重新生成可编辑目录
python _gen_customizer.py

# 4. 编辑 customize_prompts.py 内的任意内置提示词，然后：
python customize_prompts.py apply     # 用你的编辑 + 人格重建 zcode.cjs
python customize_prompts.py diff      # 列出你相对原版修改过的提示词
python customize_prompts.py restore   # 恢复出厂（移除编辑和人格）
```

每次 `apply` / 打补丁 / `restore` 之后都要重启 ZCode。

只想用人格功能？第 1–2 步就够了，跳过目录。人格与目录编辑可自由组合 —
`system_prompt.txt` 为空只是意味着不注入人格，原版 CLI 前缀保持不变。

## 兼容性

在 Windows 上针对 **ZCode 3.9.1（production 版本）** 构建并测试。路径为
Windows 风格（`%LOCALAPPDATA%`）；在其他平台上请用 `--target` / 调整
`TARGET`，指向应用 bundle 内的 `zcode.cjs`。

ZCode 应用更新会覆盖 `zcode.cjs` 并抹掉补丁 — 更新后重新运行本工具包即可。
如果更新改变了脚本所锚定的锚点文本，它们会**拒绝修补**而不是损坏文件，
你需要针对新 bundle 重新运行 `_gen_customizer.py`（或更新锚点）。

## 文件

| 文件 | 用途 |
|---|---|
| `patch_zcode.py` | 人格注入（第一条系统消息）+ 纯净备份 |
| `system_prompt.txt` | 你的人格。**特意以空白发布** — 把你自己的提示词放在这里 |
| `_gen_customizer.py` | 从纯净 bundle 重新生成可编辑目录 |
| `customize_prompts.py` | 每条内置提示词都是可编辑变量；`apply` / `diff` / `restore` |
| `prompts_data.py` | 自动生成的目录元数据 |

## 注意事项

- 让你真正的人格远离任何公开的 fork/克隆 — `system_prompt.txt` 是*你的*
  配置，本仓库中特意保持为空。
- 纯净的 `zcode.cjs.orig` 和滚动 `.bak` 备份位于应用目录中 bundle 的旁边，
  绝不会出现在这个文件夹里。
- 这里的所有操作修改的都是**你自己机器上、你自己应用的本地安装**。
  这正是本项目的意义所在。
